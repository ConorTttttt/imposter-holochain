## Current source constraints

- `dnas/game/zomes/coordinator/game/src/lib.rs`: `deal_roles` and `resend_role` use `send_remote_signal(GameSignal::RoleDealt)`; `request_role` and `my_role_leaf` use `call_remote(host, game, provide_role)`; `my_tasks` uses `provide_tasks`; `kill` sends `Killed` to the victim; `cut_lights`, `cut_comms`, `close_doors`, `start_crisis` call four host-only zome functions; `host_online` calls `ping`. These are the **complete observed remote transport call sites** in this coordinator.
- `init()` creates a **private** `CapGrant` with a listed set of eight functions but `CapAccess::Unrestricted`. A listed function is **not** equivalent to sender authorization. An additional authenticated, DNA/recipient/seat-aware policy is mandatory; any future grant narrowing must handle already-created unrestricted grants, not assume they vanish.
- `recv_remote_signal(RoleDealt)` checks the Merkle proof but not `call_info().provenance == lobby.host`, local recipient seat or current commitment hash; `request_role` likewise verifies a proof without explicitly verifying `leaf.seat == own seat` and `leaf.role_commit == current commitment`. Fix and test **before** enabling delivery, for both browser and native paths.
- Patched HWC `packages/extension/src/background/index.ts::handleRemoteSignal` rejects **every** incoming linker signal. Patched `packages/core/src/ribosome/index.ts` rejects non-local provenance; neither can be relaxed to a caller-controlled string or local ChainAuthor. Existing HWC session scope, private entry redaction and DNA-scoped AgentInfo signing already pass CI.
- Agent 3's tested H2HC runtime verifies authenticated WS/HTTP, signed DHT publication and DNA permissions, and actively closes revoked sessions. Its remote-signal frame is explicitly rejected. It is not a generic conductor proxy.
- `ui/src/holochain.ts` currently connects through `@holochain/client`'s `AppWebsocket` and clone-cell APIs. A browser injection/client adapter and UI-level signal/clone behavior need separate end-to-end acceptance. Real-time movement is via PeerKit, separate from this H2HC control-plane design.

## Smallest secure mechanism: signed, end-to-end encrypted, ephemeral private mailbox

Deliver a **dedicated allowlisted message relay over each existing authenticated H2HC WebSocket**, not an unrestricted remote zome-call endpoint. Initially only HWC-to-HWC. The gateway forwards bounded opaque ciphertext to the **currently authenticated** recipient with the exact DNA registration. It never decrypts role or task material, never signs for users, and never executes a zome. Do not add persistence to the gateway for the first milestone; offline delivery returns unavailable, and the recipient actively recovers via `request_role` and `my_tasks` on reconnection.

1. **Identity and encryption key binding.** Each HWC cell creates a dedicated per-(DNA,agent) recipient encryption keypair in an extension-owned context; use an audited RFC 9180 HPKE suite (for example X25519/HKDF-SHA256/AES-GCM subject to target browser/native support). Sign a domain-separated, versioned public-key attestation with the **existing Lair/Holochain agent signer**. The attestation binds exact 39-byte Holochain agent hash, exact 39-byte DNA hash (with checked 32-byte core mapping), key ID, epoch, validity and protocol version. Peers verify this native-Holochain Ed25519 signature and the actual bound key before encrypting; reject substituted, expired and wrong-DNA keys. Persist recipient decryption key as a non-extractable WebCrypto key in protected extension IndexedDB where supported, bound to the cell. Test Chromium + Firefox persistence explicitly; if secure persistence/key protection is unavailable, fail closed, generate a new epoch and require a new pull request. Never export the Lair signing secret into JS, WebCrypto, a page, storage, or gateway.
2. **Authenticated envelope.** Use a **single fixed versioned schema**, fixed maximum ciphertext length, canonical serialization and pinned **Holochain 0.7-generated signing/verifying test vectors** agreed with Agent 3; do not ship hand-rolled hashing or unsigned metadata. Signed fields: `version, domain, dna_hash, sender_agent, recipient_agent, recipient_key_id, message_id, created_at, expires_at, in_reply_to?, operation, payload_digest, hpke_enc, ciphertext`. Require a cryptographic sender signature from Lair and verify it against the sender AgentPubKey. Bind *all* routing/operation fields into the signed transcript and HPKE associated data. Reject mismatches between actual authenticated WS identity, envelope sender, recipient and installed cell. The gateway's `from_agent`, `to_agent` and any untrusted JSON are **hints only**; they are never authentication or WASM provenance.
3. **Strict route and authorization.** H2HC adds only `private_key_advertise`, `private_key_lookup`, `private_deliver`, and bounded acknowledgement/error frames (exact names pending Agent 3). Each requires an active **non-revoked** signed WS session, registered DNA and dedicated `private_relay` capability. Reject arbitrary `zome_name`, `fn_name`, HTTP conductor `/api` routes and unknown operations at the gateway. Recipient HWC verifies signer, DNA, local recipient, installed cell, public RoleCommit/seat membership, message kind, expiry, replay and local CapGrant authorization *before* invoking WASM. The host-function bridge has a separate `verifiedRemoteCaller` path populated only by the verified envelope, not an opt-in provenance override. `call_info().provenance` must be the true sender, never the chain author unless it really is a local call.
4. **Exact allowlist.** `role_dealt` and `resend_role` ⇒ host to bound seat only, invoke `game::recv_remote_signal` with typed `RoleDealt`. `killed` ⇒ claimed killer to exact victim, invoke `game::recv_remote_signal` with typed `Killed` after integrity checks. `provide_role`, `provide_tasks` ⇒ seated player to actual host (no other recipient), typed `call_remote` equivalent with correlation ID; returned role/task bytes encrypted to the **same requester**, and role recipient/proof/commitment checked again. `host_cut_lights`, `host_cut_comms`, `host_close_doors`, `host_start_crisis` ⇒ seated player to host, with the coordinator's impostor/cooldown/game-phase guards preserved. `ping` ⇒ host availability only. No other remote function, no browser-controlled WASM entry point, no public role reveal before the game's legitimate `reveal_all`.
5. **Confidentiality.** HPKE encrypts the inner MsgPack payload and sensitive reply; TLS/WSS still required. The gateway can see routing metadata and timing, but **not plaintext** role, proof, individual task list or kill details. Store ciphertext only transiently until socket send; do not log, archive or publish it. Reject serving secret material from DHT, HTTP read endpoints, generic discovery pages, or public HWC status. Sender and recipient extension-only code may process their own plaintext; regular web pages receive only the intended player's `YourRole` / `YouDied` display event.
6. **Replay, expiry and idempotence.** Use CSPRNG >=128-bit unique message IDs, bounded lifetime/clock skew and a per-(DNA,recipient,sender,message ID) replay ledger stored durably in cell-scoped OPFS/IndexedDB. Atomically reserve a nonce **before** a side effect; reject exact and cross-session duplicates across browser restarts and revocation/reauthorization. Bind replies to an outstanding requester, original message ID and expected host key. For mutating `killed` and host sabotage requests, make operation IDs idempotent with the target local source-chain write (or reconcile through authoritative DHT state on crash); never acknowledge delivery as successful before the intended effect is durably accepted. A duplicate or crashed attempt must never create two KillReports or sabotage moves.
7. **Disconnect/restart.** A server revocation closes all active target sockets, aborts in-flight private requests, and denies new/old bearer use; it does not wipe unrelated cells. Drop pending response correlation state on socket epoch change; reauthenticate and redo signed recipient key registration on restart. Offline push signals are not trusted as durable state. On resume, read public RoleCommit and own authenticated host/seat, then explicitly request `provide_role` and `provide_tasks` over freshly authenticated encrypted request/reply. Host `SealedRoles` remains private on the host's persisted chain. Host-offline status is **unavailable**, not a fabricated role or local fallback.
8. **Native desktop interoperability is a separate gate.** Native Holochain `call_remote` and `send_remote_signal` already use their own peer transport; an HWC-only H2HC mailbox does **not** automatically interoperate. Either implement a reviewed native authenticated adapter to this same envelope with the same capability/recipient/DNA semantics, or prove native↔HWC bridging at the gateway without proxying arbitrary calls. Until that passes, claim **browser↔browser P1 only**, not browser↔desktop full-round compatibility.

## Independent implementation gates (no security shortcuts)

| Gate | Positive acceptance | Negative acceptance |
|---|---|---|
| Wire vectors | Native Holochain 0.7 signer and independent HWC verifier agree on byte-for-byte canonical signed transcript and Ed25519 signature; native↔browser public key binding verified | Alternate serialization, wrong prefix, tampered digest/field/signature rejected before decrypt |
| Session and scope | Three independently signed Lair sessions, same exact installed host-bound DNA, private-capability grants verified | Unauthenticated WS, wrong bearer, revoked sender, unregistered DNA, foreign-DNA key, different agent, swapped recipient rejected |
| Confidentiality | Unique ciphertext per encryption, only intended recipient decrypts; gateway/artefacts/public DHT contain no role or task bytes | Eavesdropper gateway, wrong recipient key/epoch, wrong AAD, ciphertext bitflip, old key, debug-log and DHT leak scans reject |
| Receiver | Authenticated host delivers own seat's `RoleDealt`; role leaf and current root/commit verified; correct role shown privately | Guest-spoofed RoleDealt, valid proof for another seat, stale commitment, unsupported signal type rejected |
| Role/task recovery | Browser process restart and lost push followed by `request_role` and `my_tasks` returns only caller's committed role/tasks from private host state | Caller identity substitution, host impersonation, wrong seat, cross-DNA/cell request, response to wrong correlation ID rejected |
| Policy | Each of the nine allowed remote operations (two signals and seven remote-call functions, including ping, role/task recovery and four host sabotage/crisis functions) has explicit sender/recipient/function guard and local CapGrant check | Arbitrary `zome/fn`, nonexistent cap grant, ChainAuthor fallback, forged remote `provenance`, non-seat sender denied |
| Replay | Same message ID rejected after sender reconnect, recipient/worker and browser restart; subsequent new signed request permitted | Duplicate nonce, expired/future message, replay into different DNA, epoch rollback, reused response rejected |
| Side effects | Victim creates exactly one valid KillReport; host performs authorized sabotage once; negative native integrity stays active | Malformed/forged kill, duplicate/crash retry, non-impostor sabotage, cooldown bypass and forged `at_ms` rejected |
| Lifecycle | Operator revokes sender ⇒ WS close, old bearer 401, recipient untouched; fresh auth after explicit allowlist; offline role pull works | Revoked old WS/ciphertext cannot execute; no queued plaintext; offline host cannot be bypassed |
| Compatibility | Current full HWC patch, SQLite+IndexedDB collision migration, Chromium and Firefox builds, browser DHT/seat restart and real native validation remain green | No enablement of generic H2HC `/api`, no local authority fallback, no private DHT publication, no credential in storage or evidence |
| Interop and demo | Three browser identities complete an actual round (deal, role/task recovery, kill, votes, outcome), with native Valid verdicts for public moves | Browser/desktop support is NOT claimed until independently proven with mixed live peers and the same signed/encrypted protocol |

## Proposed ownership, order and safe proof of concept

**Agent 3 / gateway owner:** Confirm pinned Holochain 0.7 signature preimage vectors; implement session+DNA+recipient-scoped **opaque encrypted** relay frames, key-discovery signatures, rate/size limits, revocation gating, and no generic zome endpoint. Supply live negative WS tests. Keep server-side revocation fix and bearer separation unchanged.

**Agent 2 / HWC owner:** Implement extension-only key custody and HPKE; validate signed delivery and persisted replay before any WASM entry; add explicit remote capability evaluation with true caller provenance; never pass arbitrary `callZome` through a bridge. Add positive+negative browser tests for role/request/reply, credential hygiene and key restart. Preserve existing `apply.py` and SQLite/IndexedDB migrations unchanged until a separately pinned fully green reviewed source patch exists.

**Coordinator/UI owner (joint review):** Strengthen `RoleDealt` to require signed host, local seat, exact current commitment and proof. Strengthen `request_role`/`my_role_leaf` result seat/commitment checks. Validate kill sender/time/idempotence. Wire browser HWC app/clone/signal adapter and independent PeerKit movement tests. Run whole-round browser and mixed peer E2E.

**Permitted first PoC:** Standalone *read-only* `provide_role` and `provide_tasks` roundtrip between **two** real HWC/Lair sessions, with cryptographic binding and negative cases, after Agent 3 accepts wire vectors. Then host→seat RoleDealt push. Leave `Killed`, sabotage, all other remote calls/signals disabled until durable replay and side-effect invariants are proven. No protocol/receive-path PoC is implemented in this document because the native signing vectors, reviewed receiver authorization and durable replay boundary are not yet agreed; enabling the old handler would violate the currently proven fail-closed security guarantees.

**Review decision needed from Agent 3 before implementation:** Exact Holochain 0.7 signed-byte encoding, HPKE key-attestation format, route permission model, recipient and DNA session lookup, WS revocation handling, and whether the server will remain ciphertext-only (strongly preferred). Publish protocol test vectors + cross-implementation negative tests before either side enables delivery.
